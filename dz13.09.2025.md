# Домашнее задание: Анализ сетевых протоколов с помощью командной строки и Wireshark

## 1. MAC-адреса и протокол ARP (Уровень 2 — Канальный)

**Задача:** Увидеть свои собственные MAC-адреса и адреса сетевых устройств.

### Действия:

1. **Найти свой MAC-адрес:**
	 - **Windows:**  
		 Откройте командную строку и выполните:
		 ```
		 ipconfig /all
		 ```
		 Найдите свой Wi-Fi адаптер и строку "Физический адрес".
	 - **macOS/Linux:**  
		 В терминале выполните:
		 ```
		 ifconfig
		 ```
		 или
		 ```
		 ip a
		 ```
		 Найдите интерфейс `wlan0` (Wi-Fi) или `en0` и значение `ether`.

	 **Обсуждение:**  
	 У каждого сетевого адаптера уникальный MAC-адрес, который назначается производителем. Он нужен для идентификации устройства в локальной сети на канальном уровне (L2).

2. **Увидеть MAC-адрес маршрутизатора (шлюза):**
	 - Узнайте IP-адрес шлюза по умолчанию (в Windows — строка "Основной шлюз" в `ipconfig /all`).
	 - Пропингуйте шлюз:
		 ```
		 ping <IP-адрес шлюза>
		 ```
		 (например, `ping 192.168.1.1`). Повторите 2-3 раза.
	 - Запустите Wireshark, начните захват трафика на Wi-Fi интерфейсе.
	 - Остановите захват, примените фильтр `arp` или `icmp`.
	 - Найдите свой ping-запрос. В пакете ICMP посмотрите заголовок Ethernet II — там будут MAC-адрес источника (ваш) и назначения (маршрутизатора).
	 - Найдите ARP-пакет, который был до первого ICMP — именно он позволил узнать MAC-адрес шлюза.

	 **Обсуждение:**  
	 Компьютер узнал MAC-адрес шлюза с помощью протокола ARP (Address Resolution Protocol).

**Вывод:**  
Даже простая команда `ping` задействует протоколы Ethernet (L2), ARP и ICMP.

## 2. DNS — "Телефонная книга Интернета" (Уровень 7 — Прикладной)

**Задача:** Показать, как работает преобразование имени сайта в IP-адрес.

### Действия:

1. **Очистить кэш DNS:**
	 - **Windows:**  
		 ```
		 ipconfig /flushdns
		 ```
	 - **macOS:**  
		 ```
		 sudo killall -HUP mDNSResponder
		 ```
	 - **Linux:**  
		 ```
		 sudo systemd-resolve --flush-caches
		 ```

2. Запустите Wireshark, начните захват трафика.
3. В браузере откройте новый сайт, например, `www.example.com`.
4. Остановите захват, примените фильтр: `dns`.
5. Проанализируйте пакеты:
	 - Найдите `Standard query` (запрос) и `Standard query response` (ответ).
	 - Посмотрите поле `Transaction ID` — оно связывает запрос и ответ.
	 - В поле `Answers` будет IP-адрес сайта.
6. Примените фильтр `http` или `tls`. Найдите пакеты, где Source или Destination — это IP-адрес из ответа DNS. Это HTTP(s)-сессия с веб-сервером.

**Вывод:**  
Сначала приложение (браузер) с помощью DNS узнаёт IP-адрес, а затем устанавливает соединение по HTTP/HTTPS. Без DNS браузер не знал бы, куда обращаться.

## 3. "Трёхстороннее рукопожатие" TCP (Уровень 4 — Транспортный)

**Задача:** Увидеть установление TCP-соединения.

### Действия:

1. Запустите Wireshark, начните захват.
2. В браузере откройте HTTP-сайт, например, `http://neverssl.com`.
3. Остановите захват, примените фильтр:
	 ```
	 tcp && ip.dst == <IP-адрес сайта>
	 ```
4. Найдите начало соединения:
	 - Пакет 1 (SYN): Клиент инициирует соединение.
	 - Пакет 2 (SYN, ACK): Сервер подтверждает и сообщает свой номер последовательности.
	 - Пакет 3 (ACK): Клиент подтверждает.
5. После этого найдите HTTP-запрос `GET /` и ответ сервера `HTTP/1.1 200 OK`.

**Вывод:**  
Перед передачей данных по TCP происходит обязательная процедура установления соединения — "трёхстороннее рукопожатие". Для UDP этого нет (можно увидеть на примере пакетов DNS).

**Итог:**  
Выполнив эти задания, вы увидите работу основных сетевых протоколов: Ethernet, ARP, ICMP, DNS, TCP, HTTP/HTTPS. Даже простые действия в сети задействуют сразу несколько уровней модели OSI.
